# D4 — 변경 범위

대상 기술 tech_id: {tech_id}

**평가 질문**: 이 기술을 도입하려면 무엇을 바꿔야 하는가?

아래 6개 항목 각각을 `Y` / `N` / `unknown` 으로 기록한다.

| 항목 | 질문 |
|---|---|
| `model_retrain` | 모델을 다시 학습시켜야 하는가? |
| `model_convert` | 기존 체크포인트를 변환하는 것으로 되는가? |
| `serving_engine_change` | 서빙 엔진을 수정해야 하는가? |
| `hw_replace` | 기존 하드웨어를 교체해야 하는가? |
| `memory_add` | 메모리를 추가해야 하는가? |
| `other` | 위에 없는 변경이 필요한가? |

판정 기준:
- 근거가 그 변경이 **필요함**을 가리키면 `Y`.
- 근거가 그 변경이 **불필요함**을 가리키면 `N`.
- 어느 쪽 근거도 없으면 `unknown`. **찾지 못한 것을 `N`으로 적지 않는다.**

각 항목은 주어진 근거만 보고 판정한다. 이 기술이 어떤 종류의 기술인지에 대한 네 사전 지식으로 답을 채우지 않는다. 근거가 서로 엇갈리면 엇갈린다는 사실을 `content`에 쓰고, 더 직접적인 근거(선정 논문 원문 > 공식 문서 > 2차 자료) 쪽을 택한다.

## 출력

- `level` — 항상 `"checklist"`
- `details.checklist` — 위 6개 키
- `content` — 한국어 2~4문장. 각 항목을 그렇게 판정한 이유가 드러나야 한다.
- `citations` — 각 판정의 근거
